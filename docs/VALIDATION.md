## 人体和设备试用步骤

用户已提供真实使用截图用于离线复现；尚未完整执行下列受控检查。后续需由用户主动开启、配合动作；不得用“测试已绿”替代。

1. 开启摄像头后检查画面、镜像和叠加对齐。稳定校准后正常办公5分钟，可用率至少90%；记录每指标缺失情况。
2. 三种偏离分别5次，保持超过设置的持续时间，至少4次在持续时间后5秒内形成事件。恢复后稳定3秒应消退。头部低头须能与整体后靠/下移、抬头区分。
3. 正常办公、喝水、转头、后靠与取物30分钟，误事件不超过1次。记录文字结果，不录制影像。
4. 通知权限拒绝/允许、勿扰、关闭窗口、点通知重开、暂停到期、手动停止后锁屏唤醒逐项核对。
5. 遮挡、多人、暗光、会议占用和权限撤回时不得持续纠正；确认停止/暂停/锁屏/退出真的释放摄像头。
6. 开启检测60分钟，在活动监视器记录含子进程的CPU/内存和能耗趋势，目标平均CPU≤单核15%、内存≤300MB；记录采样频率、光线和可用指标。
7. 准备完成后断网再检测，动态核查进程网络连接与应用写盘，只允许偏好和基线数值。

因 Vision 在用户近距离截图中无法可靠取得前景肩部，已用 MediaPipe 离线对照后替换肩部后端；截图成功仍不能证明实时稳定性。阶段A未通过前，本版不作为完整产品验收。

## 0.4.0 背景模糊

- 用系统 Vision 独立人物实例选择锁定脸所属轮廓，而非全体人物前景；额外将其他检出脸区域从清晰蒙版中移除。无法选择时全幅高斯模糊，处理失败留空，UI没有原始预览层。
- 两张用户原图在内存离线处理：脸部区域边缘细节约保留93–94%，背景约保留5–6%；无目标时脸部也模糊。附加小人脸后该脸细节被抑制且 excludedFaces=1，三项坐姿指标仍可用。仅是这些静态输入证据，不能保证任意场景匿名化。
- 通过工具内存返回处理结果做视觉核对：头肩清晰、背景模糊；没有新增图片文件或录制真实相机。
- 截图冷启动分割约0.34–0.37秒，非持续实时性能结果；预览处理和姿态检测共用串行队列，可能降低采样速度。隐藏预览会跳过分割。60分钟资源和真实动作验收仍待测。
- 所有画面只存在内存，本应用模糊不改变摄像头完整输入，也不影响其他应用。

- 本次共40项核心测试通过，含模糊实例选择、弱/空/歧义蒙版和重叠旁人人脸选择。独立审查指出的旁人重叠漏遮、旧画面过期回显和重锁排队边界已修正：仅保留唯一目标检测，其余脸全部遮蔽；3秒前的结果拒绝发布；重锁用待复位屏障及相机样本时间戳截止值拒绝旧样本。
- 最终截图复现也在禁止网络的进程内通过；新增分割运行无需网络。

- 相机样本时间戳按 SDK 要求由 session.synchronizationClock 转换为 host clock 后再与重锁时间比较；时钟不可用/转换无效时不发布该帧。
