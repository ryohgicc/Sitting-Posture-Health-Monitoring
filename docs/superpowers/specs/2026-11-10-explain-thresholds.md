# Explain reminder thresholds

User: cannot tell when posture is problematic; make the boundary visible. Iteration stays within existing three metrics and reminder rules. Existing thresholds are engineering defaults relative to a personal reference, not medically established danger boundaries. A comfortable supported calibration is a user-selected reference, not proof of a healthy posture.

Use the actual judge's filtered deviation, effective entry threshold, dwell and recovery timers in a readout per metric. Show below threshold, approaching (80–100% inclusive), above threshold counting, active, recovering (55% recovery line,3s), and muted states. A marked 100% line, current converted units and sensitivity-dependent threshold explain the gauge; exact equality does not count toward dwell because production uses strict >. Missing/disabled/calibrating states show no valid readout. No duplicated timers in UI, no camera/keypoint history. No threshold or notification behavior change. Explain validation mode, snooze and cooldown separately so a visible event is not a promise of a new notification.

References checked 2026-11-10: Open Posture personal baseline/sustained assessable drift; posture-check live deltas and sensitivity tuning. OSHA neutral supported positioning and movement guidance: https://www.osha.gov/etools/computer-workstations/positions/ . OSHA does not establish our11.5°/18%/8° cutoffs. Head measurement is face pitch, shoulder measurement is projected shoulder-line angle; neither is neck/spine pathology. Lateral is change in nose-to-shoulder-center offset divided by current shoulder span, not trunk angle.
