# 坐姿提醒工具 PRD v1.0

日期：2026-11-09  
状态：需求定稿，供后续开发使用；本次只交付文档，尚未开始开发或调用摄像头。  
本版替代 v0.1；旧版保留作为草案记录，后续以本版为准。

## 1. 产品目标与已确认选择

用户长时间办公时，肩膀容易向前缩并出现酸感，希望应用持续观察姿态变化，在明显偏离一段时间后温和提醒，减少自行留意的负担。

| 项目 | 已确认范围 |
|---|---|
| 平台 | 仅当前这台 Apple Silicon Mac，不承诺其他设备兼容 |
| 使用方式 | 桌面应用，菜单栏常驻，关闭设置窗口继续检测 |
| 摄像头 | 内置摄像头，正面拍摄完整头部和双肩 |
| 首版检测 | 低头、左右偏斜、肩线变化；分别通过实测后启用 |
| 提醒 | 无声系统通知，遵循系统专注与勿扰设置 |
| 启动 | 用户手动启动应用、手动开启监测 |
| 数据 | 本机处理，不保存照片、视频或历史统计 |

成功标准是及时发现持续姿态变化、减少误报和打扰。个人校准是舒适参考姿态，不是医学认证的标准坐姿；不要求用户整天保持同一个姿势。产品不诊断酸痛原因，也不以纠正骨骼或治疗疼痛为承诺。

## 2. 首版范围与检测边界

### 2.1 必须包含

- 摄像头权限说明、画面预览、关键点叠加、个人基线校准及重新校准。
- 低头、左右偏斜、肩线变化三个候选指标，各自可用性检查与状态展示。
- 时间平滑、持续偏离判断、提醒合并、冷却和恢复。
- 菜单栏常驻、无声系统通知、稍后提醒、暂停检测、停止检测。
- 摄像头占用或失败、锁屏、休眠、唤醒等状态处理。
- 独立、可关闭的活动提醒，不依赖姿态模型判断用户是否已运动。

### 2.2 各指标的产品定义

| 指标 | 可使用的信号 | 提醒与限制 |
|---|---|---|
| 低头 | 相对个人基线的头部俯仰变化；必要时结合面部头姿 | 必须验证能与整体后靠、下移区分。只有二维头肩位置变化时，显示“头部位置变化”，不能直接断言低头 |
| 左右偏斜 | 头部相对肩中点的横向偏移，辅以肩线角度 | 短暂转头和取物不提醒；转椅子等大幅方向变化时暂停有关指标 |
| 肩线变化 | 左右肩连线相对基线的角度变化 | 不要求绝对水平，不将个人原有不对称标记为异常，不诊断高低肩 |

关键点预期包含左右肩，以及模型提供的鼻、眼、耳等头面点；肘部仅作辅助，髋、膝不是必需输入。头肩距离、脸部尺度等可以辅助分析，但不直接当作精确三维距离。

### 2.3 明确不包含

- 正面精确识别圆肩、肩膀向前卷、颈椎前伸距离。
- 二郎腿、骨盆位置、腰椎曲度、疾病风险及医学健康评分。
- 多人身份识别、自动识别所有视频会议、自动证明用户已站立活动。
- 登录自启动、启动应用即自动开启摄像头、历史趋势、账号和云端分析。
- Windows、手机端、侧面或多摄像头模式、App Store 上架、多设备分发。

圆肩虽是最初困扰，但用户已接受首版先做上述三项姿态信号。后续增加圆肩检测，需要另行定义和验证，不在本版中顺带加入。

## 3. 技术路线与开源经验

采用原生 macOS 菜单栏应用作为产品外壳，建议 Swift/SwiftUI、AVFoundation 采集和系统通知。检测后端先验证系统视觉能力，必要时对比 MediaPipe 身体关键点与面部头姿；最终根据当前设备实测选择，不预先承诺模型效果。

| 考虑过的路线 | 结论与原因 |
|---|---|
| 原生 Mac 应用＋本机姿态检测 | 采用；符合仅当前 Mac、菜单栏常驻和权限管理需求 |
| 网页或浏览器扩展 | 不采用为成品；窗口与浏览器生命周期不符合已确认的常驻需求 |
| 跨平台桌面容器 | 本版不采用；Windows 不在范围内，先避免增加依赖 |
| 侧面摄像头或单目三维估计 | 本版不采用；用户已选内置正面拍摄，圆肩不在首版承诺中 |

借鉴 [Upright](https://github.com/LinklyAI/upright) 的个人基线、尺度归一化、EMA 平滑、不同进入/退出阈值和持续时间；借鉴 [Pose Nudge](https://github.com/DDULDDUCK/pose-nudge) 的桌面常驻与摄像头生命周期；借鉴 [LearnOpenCV 健身示例](https://github.com/spmallick/learnopencv/tree/master/AI-Fitness-Trainer-Using-MediaPipe-Analyzing-Squats) 先检查拍摄条件再判断的做法。

不直接照搬健身角度阈值、任意扣分的“健康分”、保存校准照片、离开画面即计作休息等行为。复用算法思想和成熟模型；复制代码、打包模型前核对对应许可。详细证据见同目录《GitHub坐姿与健身骨架项目调研》。

## 4. 用户流程与界面

### 4.1 首次使用与校准

1. 用户手动打开应用，菜单栏显示“未开启”；仅启动应用不访问摄像头。
2. 用户点击“开启监测”，先说明本机处理和摄像头指示，再申请权限。拒绝后展示恢复方法，仍可使用活动提醒。
3. 打开镜像预览，检查头和双肩是否完整可见；可开关关键点叠加。数据与镜像坐标统一，不反转左右判断。
4. 提示按平常工作位置坐稳、肩膀放松、腰背与手臂有支撑，不刻意挺胸或夹肩。
5. 采集约 10 秒稳定有效画面，以稳健统计量建立基线；不足时显示原因，不使用残缺校准结果。
6. 展示各指标是否可用，进入监测；窗口可以关闭，菜单栏继续显示状态。

仅持久保存设置和数值校准参数，可一键清除；不保存用于校准的照片。每次重开监测检查输入是否适用。调整椅子、屏幕角度或工作位置后可一键重新校准；不能可靠自动发现所有摆位变化，因此使用说明明确提醒用户。首版不自动追随偏离姿态更新基线。

### 4.2 界面范围

| 界面 | 核心内容 |
|---|---|
| 菜单栏菜单 | 当前状态、打开状态页、稍后提醒10分钟、暂停检测30分钟、停止检测、活动提醒开关、退出 |
| 状态与校准页 | 可选摄像头预览/关键点、校准与重校准、各指标可用性和相对基线变化、采集状态 |
| 设置页 | 检测项开关、灵敏度、持续时间、冷却时间、活动提醒间隔、本地参数清除 |

菜单栏状态至少区分：未开启、等待校准、监测中、部分指标不可用、暂时看不清、已暂停、摄像头故障。模型故障和不可判断不能显示为“坐姿良好”。

## 5. 判断与提醒规则

流水线：摄像头 → 关键点/头姿 → 输入可用性 → 相对个人基线的指标 → 时间平滑 → 持续偏离 → 提醒。

### 5.1 默认参数

以下为首版产品初值，灵敏度对应的实际角度/比例阈值由技术验证确定，不在文档中编造标准角度。

| 参数 | 默认值 | 调整规则 |
|---|---|---|
| 稳定校准 | 约10秒 | 输入不稳定时重新采集 |
| 推理频率 | 约3–5帧/秒 | 根据稳定性与能耗调整，不必全速处理视频 |
| 偏离持续时间 | 20秒 | 设置可选10/20/30秒 |
| 恢复持续时间 | 3秒 | 开发内部参数，避免边界闪烁 |
| 同类提醒冷却 | 10分钟 | 设置可选5/10/20分钟 |
| 灵敏度 | 标准 | 可选低/标准/高，实际阈值通过验证确定 |
| 活动提醒 | 每45分钟，默认开启 | 可选30/45/60分钟或关闭 |

活动提醒默认开启及以上数值属于本版产品决定，未将其描述为医学硬性间隔。

### 5.2 可用性与误报处理

- 每个指标独立检查必需关键点与置信度。某项缺失不影响其他确实可用的指标。
- 遮挡、输入中断、明显尺度跳变或不适用方向时，相关指标进入“不可判断”，清空其偏离和恢复计时；恢复有效输入后重新累计。
- 正常短暂喝水、转头、取物不得触发通知；持续的大幅转身可能无法与姿态变化区分，需降级或说明限制。
- 使用单人场景，不保证自动识别所有多人入镜。若后端可靠发现多人，则暂停判断；无法确定人数时不能宣称已排除他人，也不因模型只返回一个人就认为场景安全。无法稳定锁定目标或关键点有歧义时暂停判断。
- 用真实时间计算持续时长，不用固定帧数代替；睡眠、取帧中断等空档不计入异常持续时间。
- 进入异常与恢复使用不同阈值，减少边界反复切换。正常波动不自动成为警报。

### 5.3 通知行为

- 只发送无声系统通知；不播放提示音、不强制浮层、不抢焦点、不模糊用户工作内容。
- 通知描述观察到的变化，如“头部低垂了一会儿，换个姿势或活动一下吧”。未验证能准确识别低头时，改为更中性的“头部位置持续偏离参考姿态”。
- 多个指标同时满足条件时合并；新增指标至少与上一条姿态通知间隔60秒，避免交错轰炸。
- 同类通知在冷却期内不重发，恢复不清除冷却。冷却结束后若仍持续偏离，可再次提醒；这不等于用户发生了新的异常事件。
- 通知被拒绝时，在状态页和菜单栏标明“系统通知未开启”，提供设置指引；保留状态提示，不偷偷改用声音。
- 系统专注/勿扰可能延迟或隐藏通知，应用不绕过系统策略，也不把请求发送等同于用户已看到。

## 6. 后台、暂停与摄像头生命周期

| 操作或状态 | 摄像头与判断 | 提醒与计时 |
|---|---|---|
| 关闭设置窗口 | 继续监测 | 继续通知和计时 |
| 稍后提醒10分钟 | 继续采集与判断，界面明确标注 | 暂停姿态和活动通知，不积攒补发；到期重新评估当前状态 |
| 暂停检测30分钟 | 立即停止采集、释放摄像头、清空偏离计时 | 暂停两类通知及活动计时；到期解锁且条件有效时恢复，界面明确说明自动恢复 |
| 停止检测 | 立即释放摄像头，不自动恢复 | 停止姿态通知；独立启用的活动提醒可继续，界面明确说明 |
| 锁屏、系统休眠 | 停止采集并清空偏离计时 | 暂停活动计时；仅在锁屏前正在监测时，解锁后恢复，保留原有暂停截止时间，不覆盖用户停止操作 |
| 摄像头失败、权限撤回或被占用 | 停止采集与判断，提示原因；用户手动恢复 | 不反复弹错，不发送姿态纠正，活动提醒仍可独立工作 |
| 退出应用 | 释放摄像头并退出进程 | 所有通知和计时停止 |

“监测中”意味着摄像头持续使用，即使只低频推理，系统指示灯也可能一直亮。用户可随时停止。应用不承诺自动识别会议，也不承诺与所有视频软件共享摄像头。

活动提醒是用户开启后的工作计时，锁屏、休眠与明确暂停期间不累计。离开画面不自动算作完成活动；“我已活动”按钮手动重置计时。姿态与活动提醒撞到同一分钟时合并为一条，计时到期后发送一次即可，不逐分钟催促。

## 7. 隐私与数据

- 原始帧只在本机内存处理，不上传、不录像、不截图、不写日志；无云端推理与遥测。
- 关键点仅用于当前判断，不保存逐帧轨迹、会话记录或每日历史统计。
- 只保存必要设置、数值基线和校准适用性元数据；可清除，清除基线后需重新校准。
- 检测模型在本地运行；若需下载模型，说明来源和用途，完成准备后须能断网运行。
- 应用不隐蔽采集，菜单栏和系统摄像头指示保持可见。

## 8. 分阶段交付与验收

### 阶段A：检测可行性验证

验证版包含摄像头预览、关键点叠加、校准和指标状态，不先堆完整应用功能。用户主动开启摄像头后，在实际桌椅和内置摄像头条件下验证。

优先验证 macOS 系统视觉能力；低头难以区分或关键点不稳时，再对比 MediaPipe 身体关键点与必要的面部头姿。比较稳定性、误报、低频表现和资源占用；只保留最终选定后端，不默认把两套都打包。

通过条件：

1. 正常办公姿态下，头和双肩的有效识别帧占有效采集时间对应帧数的至少90%，每次试用不少于5分钟，并列明各指标可用率。
2. 三个候选指标分别进行至少5次明显偏离与恢复，至少4次在达到持续时间后的5秒内进入预期提醒状态。人工动作仅验证功能，不证明医学有效性。
3. 正常打字、喝水、短暂转头、后靠、取物合计连续试用30分钟，错误触发目标不超过1次；记录问题场景，不保存视频。
4. 区分低头与整体下移；不能区分时只能交付中性头部位置变化提示，并明确该项降级，不能按“低头检测成功”验收。

未通过的指标不启用、不静默删除验收要求。若需要减少已确认的三项检测范围，先报告原因与可行替代；不能靠把所有检测项关闭来宣称通过。阶段A若整体不可行，应停在验证结果，不继续包装成完整成品。

### 阶段B：常驻应用

阶段A确定检测后端后，补齐菜单栏、状态页、通知、暂停与故障处理。功能验收：

1. 校准、重校准、每项检测开关及不可判断状态与本文一致；暂停与恢复不沿用中断前的偏离计时。
2. 关闭窗口持续工作；停止、锁屏、休眠、退出后，实际确认采集停止、摄像头释放。
3. 实际验证正常系统通知及拒绝权限路径；勿扰下遵守系统设置，不自行弹窗。
4. 合并、冷却、稍后提醒与活动计时按规则工作。长时间窗口可通过可控时钟测试，但至少有一轮真实摄像头和真实通知的端到端试用。
5. 遮挡、离席、光线不足、取帧失败及目标不稳定时，相关指标停止纠正提醒；多人仅按已验证的后端能力验收，不伪称全面识别。
6. 摄像头被占用、权限撤回、睡眠唤醒后不崩溃、不循环打扰，提供可操作恢复入口。
7. 核查网络请求、日志和文件：无影像、关键点外传或影像落盘；准备完毕后断网仍能检测。
8. 当前设备连续运行60分钟，记录应用及子进程 CPU、内存和系统能耗趋势。平均 CPU 以100%代表一个逻辑核心，优化目标≤15%；合计内存目标≤300 MB。报告采样频率和方法，未达标时优化或明确调整，不能隐去结果；这些是工程目标，不是已达成指标。

### 交付内容

- 可在当前 Mac 启动的本地 `.app`、必要构建脚本及源代码。
- README：启动方式、权限、校准、菜单栏操作、检测限制、停止与卸载方法。
- 验证报告：实际可用指标、误提醒表现、资源占用、已知限制及未通过项。
- 当前 Mac 的实际运行验证；开发者证书签名、公证和公开分发另列范围，不在未验证时承诺双击即可无提示运行。

## 10. 2026-11-09 多人办公场景修订

用户明确要求背景多人仍可使用。本条替代前文“单人场景、发现多人即暂停”的限制：应用跟踪一个前景使用者，背景可有多人；这不是多用户身份识别。

- 默认选择足够大且居中的前景人脸，位置跟踪，不存人脸身份信息。相似大小多人无法区分时提示点预览中自己的脸选择。
- 使用绿色框标明当前目标，只关联目标脸部对应的骨架；不借用同事的肩部关键点。
- 锁定后不因其他人入镜而切换。目标丢失超过2秒、遮挡或候选不明确时暂停，要求手动重新锁定。重锁、重开检测后需重新校准，以免套用他人的基线。
- 人脸角度不依赖人体骨架识别；骨架缺失时继续可用头部指标，肩线/偏斜仍显示不可判断。这不代表缩减最终三项验收要求。

## 14. 2026-11-10 可解释提醒边界

用户要求知道何时超过临界值。三项工程提醒线公开当前值、单位、个人参考变化及灵敏度缩放：标准头部0.20rad≈11.5°、左右比例0.18、肩线0.14rad≈8°。100%为进入提醒线，80%仅为接近提示；严格超过后按实际判断计时，默认20秒。事件后55%恢复线内稳定3秒，显示恢复进度。缺失/关闭/校准中不显示正常。验证模式、静默及冷却区别说明，不承诺超线立即有系统通知。以上不是医学损伤边界，校准需舒适放松有支撑，不能靠校准证明健康。
